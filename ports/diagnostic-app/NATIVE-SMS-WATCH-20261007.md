# IMS 自身权限查询与原生短信恢复，2026-10-07

诊断工具 0.9.13、Android 11 IMS 0.4.7、API30 模块 0.9.6-trial 和现代模块
0.2.6 已完成统一构建与签名验证。当前 raphael Android 11 已安装新版并实际重启，
IWLAN／QNS／IMS 三组件的已安装 APK 和模块挂载字节均与构建产物一致。

## 本次修改

- IMS 服务以自身应用 UID 在后台查询所选订阅的原生 IMS 短信支持状态，向诊断
  应用提供查询时间、结果、请求计数。未知和超时不会当成不支持。
- 实机发现电话权限已授予，但新查询被隐藏接口策略拒绝。IMS 的系统应用 manifest
  增加 `android:usesNonSdkApi="true"`；通过实际 ApplicationInfo 和服务自身查询
  分别核实。未更改全局隐藏接口设置。该声明的作用范围是这一个系统应用。
- 已校准的 API30 raphael ROM 在注册和能力就绪、当前卡与所有者匹配、通话和短信
  空闲时，连续确认原生短信不支持才请求现有客户端重绑。资格需持续 20 秒，再有
  至少三次间隔 3 秒的否定样本；每个 feature 最多三次，间隔至少 120 秒。
- 注册中断及 feature 移除会清空旧资格和失败样本。已接受请求与并发 DOWN 的记账
  分开处理，执行前仍重新检查所有者、注册和空闲状态。
- 空闲条件增加短信 TX/RX 等待集合、处理与完成回调、ACK 写出以及五秒静默期。
  这些条件同时保护自动恢复和现有手动重绑。
- 诊断应用增加中文恢复状态和采样年龄，支持旧 provider 的无扩展快照，并拒绝
  部分或无效的新字段组。升级时先更新诊断消费者，再更新 IMS 生产者。

## 实际验证和边界

82 项 Java 合约检查覆盖实际 gate、activity tracker、reader 的确认、限频、
未知、上下文、异常和并发退场记账；Android/Binder 是主机 stub。63 项消费者
检查覆盖实际协议校验器。生成后的 Kotlin 和 API30／API31 服务均已编译。

实机服务自身 UID 的查询有效；空闲重载后观察到启动初期短暂未就绪，随后恢复。
完整观察窗口内自动请求数为零，状态是 `ready-without-reproduced-mismatch`。
因此**自动重绑分支尚未在实机触发验证**，不能把自然就绪写成自动重绑成功。

一次显式选择测试卡的 191 通话接通，发送 294 帧、交给播放 302 帧，挂断返回
200；实际听感仍未确认。一次原生 85075 INFO 发送返回 RESULT_OK、网络错误 0；
收到并成功确认四段，合并为一条系统收件箱短信并显示新通知。业务期间 Phone、
IMS 代次和全替换所有者保持稳定，未手动重绑或重载。

短码策略在业务验证之后恢复，所需空闲 Phone 重载之后连续三次原生短信就绪。
新模块实际重启之后再次连续三次确认服务自身查询及分发器就绪，三项安装和挂载
文件均匹配，全替换 owner 保留。启动期间暂态和检查错误均保留在报告中。

初次热更新绑定失败、初版查询被隐藏接口拒绝和主机 dumpsys 字段识别失败都有
独立原始失败报告；后来的直接 ApplicationInfo 检查和成功记录不改写旧失败。
没有更改 APN、vendor、modem、CNE 或内核。本次未使用账号登录。

现代端重新构建、签名和打包通过；API30 校准恢复不会在 API31–37 上启用。
现代 Android 实机运营商业务、现代 app 自身 UID 控制、真实双活 SIM、持续稳定性
和实机自动重绑分支仍待验证，完整 Android 11–17／双卡目标保持未完成。
